# Energy Wise

Створи внутрішній веб-застосунок «АСКОЕ — Аналітика споживання електроенергії та підбір КГУ» — заміну Excel-файлу з погодинним обліком споживання електроенергії та розрахунком режимів роботи когенераційних установок (КГУ).

1. Призначення

Застосунок приймає погодинні дані споживання електроенергії підприємства за рік (12 місяців × до 31 дня × 24 години), дозволяє підібрати конфігурацію когенераційних установок (КГУ, до 5 машин) і автоматично рахує:

зведену річну та помісячну статистику споживання;

% завантаження обраних КГУ по кожній годині;

статус роботи (норма / допуск / аварія) для звичайного та острівного режимів;

річний підсумок по годинах у нормі/допуску/аварії, помісячно і за рік.

3. Панель конфігурації (застосовується до ВСІХ місяців)

Блок налаштувань з такими полями:

Машина 1–5: випадаючий список з довідника КГУ (або «не використовується» — порожньо), для кожної обраної машини автоматично підтягується потужність, кВт.

Сума потужностей (1–5) — авторозрахунок.

Режим аналізу потужності: перемикач «Разом (сума 1–5)» / «Окремо по машинах» (закладено на майбутнє, за замовчуванням — «Разом»).

Потужність для розрахунку — те значення (кВт), відносно якого рахується % завантаження в кожній годині.

Допустимі діапазони роботи (числові поля, %):

Звичайний режим — мінімальна норма, % (за замовч. 35)

Звичайний режим — допуск від, % (за замовч. 35)

Звичайний режим — максимум, % (за замовч. 100)

Острів — мінімум, % (за замовч. 35)

Острів — максимум, % (за замовч. 90)

Зміна будь-якого параметра миттєво перераховує статуси на всіх місячних вкладках і в зведеній аналітиці (реактивний стейт, без збереження/перезавантаження сторінки).

4. Введення даних споживання

Для кожного з 12 місяців — таблиця «Час × Дата»:

рядки: 24 години доби у форматі 00:00-01:00 … 23:00-24:00;

стовпці: дні місяця (28–31 залежно від місяця, рік 2026);

клітинки: погодинне споживання, кВт·г (ціле число).

Способи введення даних:

ручне редагування клітинок прямо в таблиці (як у таблиці/сітці, inline-edit);

імпорт з Excel/CSV файлу (кнопка «Завантажити дані» на кожній місячній вкладці або одразу на весь рік), з парсингом такої ж структури «час × дата»;

можливість очистити місяць.

5. Розрахунки по кожній годині (для кожного дня в місяці)

Для кожного рядка-години місячної таблиці розрахувати:

Середнє, кВт·г — середнє значення по всіх днях місяця в цій годині;

Макс, кВт·г — максимум по днях;

Мін, кВт·г — мінімум по днях (ігноруючи порожні/нульові як відсутність даних, якщо потрібно — уточни логіку через порожні клітинки);

Ліміт, кВт·г — контрактний ліміт потужності (окреме поле налаштувань, спільне значення для місяця/року);

Перевищення, % — на скільки середнє перевищує ліміт (якщо перевищує);

Зона навантаження — на основі процентилів середніх значень по місяцю: 🔴 Пік якщо середнє ≥ 75-го процентиля, 🟢 Мінімум якщо ≤ 25-го процентиля, інакше 🟡 Норма;

% завантаження (КГУ) = Середнє / «Потужність для розрахунку» (з панелі конфігурації) × 100;

Статус (звичайний режим):

🔴 Аварія (>Х%) якщо % завантаження > «максимум, %»;

✅ Норма якщо % завантаження ≥ «мінімальна норма, %»;

🟡 Допуск (≤2год) якщо % завантаження ≥ «допуск від, %», але нижче норми;

інакше 🔴 Аварія (<Х%).

Статус (острівний режим):

🔴 Перевищення (>Х%) якщо % завантаження > «острів — максимум, %»;

✅ Норма (острів) якщо % завантаження ≥ «острів — мінімум, %»;

інакше 🔴 Низьке (<Х%).

6. Зведена аналітика (річна)

Окрема сторінка/вкладка «Аналітика»:

Селектор місяця для перегляду деталей (перемикач/dropdown).

Річна зведена таблиця по 12 місяцях зі стовпцями: Місяць, Загальне кВт·г, Макс інтервал кВт·г, Мін інтервал кВт·г, Середнє кВт·г, Середньодобове кВт·г, Година максимуму, Година мінімуму. Останній рядок — «РАЗОМ / СЕРЕДНЄ» з підсумками/середніми по року.

Блок «Деталі обраного місяця»: загальне споживання, максимум/мінімум за годину, середнє погодинне, години пікового/мінімального навантаження, середньодобове споживання — для місяця, вибраного в селекторі вище.

Річний аналіз роботи КГУ — таблиця по 12 місяцях зі стовпцями: Норма (зв., год), Допуск (зв., год), Аварія (зв., год), Норма (остр., год), Поза межами (остр., год), % часу в нормі (зв.), % часу в нормі (остр.). Підсумковий рядок «РІК (РАЗОМ)».

Невеликі картки/лічильники: Годин у нормі (рік, зв.), Годин у допуску (рік, зв.), Годин аварійних (рік, зв.), Годин у нормі (рік, острів) — з максимумом «24 години» як орієнтир на добу для наочності.

7. Візуалізація

Додай графіки (бібліотека на вибір Lovable, напр. Recharts):

лінійний/стовпчиковий графік річного споживання по місяцях;

графік погодинного профілю споживання обраного місяця (середнє/макс/мін по годинах доби);

кругова/стовпчикова діаграма розподілу годин по статусах (норма/допуск/аварія) за рік і за обраний місяць, окремо для звичайного та острівного режимів.

8. UI/UX вимоги

Інтерфейс українською мовою.

Структура: бокове меню або вкладки — «Аналітика» (головна), «Січень» … «Грудень», «Довідник КГУ», «Налаштування».

Кольорове кодування статусів: зелений/✅ — норма, жовтий/🟡 — допуск, червоний/🔴 — аварія/перевищення.

Таблиці з великою кількістю стовпців (24 години × 31 день) повинні мати горизонтальний скрол, закріплений перший стовпець (години) і закріплений заголовок (дати).

Адаптивність для перегляду на планшеті; повноцінна робота на десктопі — головний сценарій використання.

Дані зберігати в стані застосунку (з можливістю зберегти в базу — Supabase, якщо Lovable підключає — щоб дані не губилися при перезавантаженні сторінки).

Кнопка «Експорт у Excel/CSV» для зведеної річної таблиці та для будь-якого місяця.

9. Технічні примітки

Це внутрішній інструмент для власного використання компанії (не публічний продукт), автентифікація не обов'язкова, але бажано просту защиту доступу (пароль/логін), якщо Lovable це підтримує просто.

Пріоритет — точність розрахункової логіки з розділу 5–6, а не складний дизайн.

Усі формули мають перераховуватися динамічно при зміні вхідних даних або параметрів конфігурації, без ручного «Розрахувати».
